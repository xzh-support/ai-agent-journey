Token ：
    最小信息单位 是ai处理文本时不可再分的最小单位 将输入文本拆分成 一个个小片段 一个片段对应一个Token
    token序列 通过这些顺序排列形成Token序列 模型通过理解序列来处理语义
    实例 : 我想吃香蕉 模型拆为“我”“想”“吃”“香蕉” 一句话变成了四个token
上下文窗口(Contextwindow) :
    定义了模型单次能处理的最大Token数量,决定了AI一次对话能看到多少内容
    注意！不是窗口越大模型越聪明 如果一次的内容过多可能会被无关内容干扰 一次的内容过少可能会AI答不出来
    所以关键是怎么把任务交代清楚 所以引出了Prompt
Prompt :
    也就是提示词 是用户向AI传达任务意图的核心工具与表达方式
    早期使用 直觉交互 1简单输入 他就能给答案 2 零门槛人人能用 3发现同一个问题 4 不同问法结果差距很大
    具体提问效果 1 明确角色 2 指定任务 3 指定结构 4让ai输出更具体更有结构更接近用户预期的结果
Prompt Engineering :
    提示词工程 本质是给AI写一份清晰的工作说明书 系统的告诉它角色 任务 标准 
    工作说明书四要素 1角色定位 2任务描述 3背景信息 4验收标准
    提示词再清楚也无法完成模型不知道的东西 当被问到训练数据中不存在的知识时，ai会产生”幻觉“--一本正经地编造看似合理实则虚假的回答
    于是出现了RAG
RAG :
    全称Retrieval-Augmented Generation 检索增强生成概念 也就是让ai先查资料再回答 核心目的不让ai只凭训练记忆回答 而是先从外部知识库检索相关资料 再基于资料生成回答
    企业内部文档 产品手册等私有知识从未出现在通用模型的训练数据 没有RAG时ai对此类问题天然存在知识盲区
    工作流程 通过存入知识库——》检索相关内容——》交给AI——》基于资料回答 让ai的回答有据可查
    核心逻辑 先检索外部知识 再基于检索结果生成回答
Embedding ：
    将自然语言文字转化为高维数字向量，使计算机可以通过数学运算比较语义相似度，而非理解文字含义
    也就是把文字变成一串数字 将自然语言映射到高维空间 每个词或句子对应一个坐标点
    计算机看不懂文字的意思 只通过比较数字之间的距离 量化文本的语义接近程度
    比如“怎么申请退款” 和 “订单取消后钱怎么退” 字面不同语义相近 比关键词搜索更智能
    但是RAG解决了AI的知识盲区问题 但Ai仍然只能给建议和生成文字，无法真正执行操作 这催生了Tool Calling的出现
tool calling ：
    tool calling 让ai只生成文字进化到能调用外部工具执行动作 相当于给AI装上了手 使其具备真正的行动能力
    ai可以调用外部工具后 出现了问题 每个工具接口不同 接法各异 导致开发和维护成本急剧上升缺乏统一标准
    工具接入涉及描述规范 参数传递 权限管理 结果返回 安全控制等多个维度
    于是出现了MCP
MCP :
    MCP是AI连接外部工具的标准协议 可以类比为AI世界的usb-c 用统一的接口标准替代各自为政的碎片化连接方式
    以前接工具像焊电线 每个ai应用接入不同工具都需要单独开发适配代码 
    MCP 统一解决了工具暴露方式 参数传递规范 调用结果返回 权限安全控制等工具接入的核心问题 是AI工具生态的连接层
    让ai从单纯的聊天框进化为可接入各种插件和工具的系统平台
    影响ai效果的不仅仅是模型和工具 还有个关键的东西是它当时到底看到了什么信息 也就是每次任务的时候系统给他准备了哪些信息 这催生了context engineering
    Prompt Engineering不是过时了而是不够用了 当AI应用从简单问答走向复杂场景 单条指令已无法管理系统级的信息流设计
Context Engineering :
    需要系统设计每次任务中AI应获取的信息组合: 历史对话 用户资料 数据库结果 公司规范 工具状态
    和Prompt Engineering 的对比 一个是写好一条指令 关注单次对话的表达 一个是设计整个信息流 统筹全局信息的架构
    就像AI智能客服 一次高质量回复需要整合客户身份 购买历史 投诉记录 退款政策 是非需要升级人工等多维信息
    核心不是给AI更多信息 是投喂刚好需要的信息--不多不少 恰到好处 避免信息不足 过载或过期
    每次任务都要交代相同的要求极其低效 于是催生了Skill功能——将特定AI能力一次性封装,后续可反复调用
Skill :
    解决不想每次都重新教AI一遍 将重复性任务的要求封装为可复用模块 一键调用 例如每周写周报
    将工作中的具体要求与格式偏好固化为可储存的Skill定义 下次只需一句话调用就可以
    当AI具备了知识检索 工具调用和技能复用的能力后，自然演进到能否自主完成复杂任务--这正是Agent要回答的问题
Agent ！！ 
    Agent不是更聪明的聊天机器人 而是能围绕目标自主拆解步骤 选择工具 观察结果并持续调整的AI系统
    核心能力是围绕目标进行自主规划--自己拆解步骤 选择合适工具 观察执行结果 根据反馈动态调整策略
    三种AI的区别 从聊天机器人 到Tool Calling（调用外部工具） 再到Agent AI的能力逐步升级-- 从被动回答到执行单步动作 再到围绕目标自主推进
    编程场景天然适合Agent 代码文件结构明确 报错信息具体 测试结果可验证 版本控制可追溯 形成完整的自主执行闭环
Vibe Coding
    是一种全新编程范式--程序员从写代码转变为描述目标 由AI生成实现 程序员负责验收和调整
    改变了程序员的工作重从写具体实现转移到需求定义 任务拆解 架构设计 代码审核 和AI Agent管理上
    Agent的风险 Agent越强大越自主 潜在风险也越大 可能犯错 误删文件 生成不安全代码 执行跑偏 消耗过量资源
    Agent不是越自由越好 Agent必须通过工程约束来保障安全可靠  于是催生出了Harness 
Harness Engineering :
    是一套完整的工程约束系统 涵盖权限控制 执行沙盒 验证输出 人工审批 安全边界 回滚机制等多个组件
    Harness是Agent的控制系统 像汽车的安全带 方向盘 和刹车 模型是发动机
    比如你让Agent帮你清理文件 可能会误删重要文件 有harness只能访问指定文件夹以及权限边界
企业的真正需求:
    不是看起来聪明的Agent 而是安全可控 可追踪 能被验证的Agent--AI落地的难点从模型只能转到系统可靠
Loop Engineering ：
    Harness确保Agent不穿祸，loop确保Agent能成事--前者是安全约束 后者是自主闭环执行与持续纠错的能力
    也就是自动导航和纠错系统 自己规划自己改错
    通常包含目标拆解 自检复盘 自动重试 进度留存 达标判定和成本管控 驱动Agent持续迭代直到任务圆满完成
AI落地的新趋势 ：
    不仅需要安全可控 更要能自主闭环--AI落地正从拼系统安全走向拼任务闭环能力的新阶段
workflow（N8N Coze） :
    AI怎么进入业务流程
    真实业务是一条涉及多系统 多步骤的完整流程--从表单提交到客户分类 销售分配 邮件发送 数据写入 环环相扣
    Workflow的价值不在于增强模型 而在于将AI API 数据库 消息系统 人工审批等串联为完整的业务流程
Workspace Agent :
    Workflow 一条流程 Workspace Agent 一个岗位助手长期待在团队里
    需要深度理解团队长度积累的全部上下文--项目 文档 分工 客户关系 敏感信息和审批流程
